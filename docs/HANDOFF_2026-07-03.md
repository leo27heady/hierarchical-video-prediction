## 6. THE ARCHITECTURE DIAGNOSIS (external red-team, VERIFIED — drives the next step)

1. Our hierarchy is a SPATIAL pyramid at a single temporal clock (per-frame coarse+fine, joint
   full-rate AR rollout; coarse used only as longer cheap context). We built MilliVid's DiT parts
   (`hvp_rev/faithful_nets.py` transcribes `dit_per_token_c.py`/`adaptivity.py`/
   `model_video_universal.py`) but NOT MilliVid's benefit mechanism.
2. MilliVid's AE also has NO temporal downsampling (4 levels, spatial ÷2: 16²→8²→4²→2², 32ch,
   per-level decodable). Its benefit = the COARSE-FIRST MULTI-RATE ROLLOUT
   (`millivid/source/.../strategy_millivid.py`, [3,12,48,192] frames/level, ~768 tokens/level):
   generate long coarse span first, refine conditioned on the coarse FUTURE. CW-VAE's benefit =
   genuine slow clock (level l ticks every k^(l−1), k=6). We implemented NEITHER.
3. REGIME CAP: loop period ≈48 == flat-long's affordable window → flat can cover the whole
   memory horizon at full res → hierarchy can only ever be an efficiency point here, never a
   capability necessity. This is WHY papers' clear benefits don't reproduce as capability wins.
4. Therefore the honest current claim: "at fixed token budget, coarse-level context packing beats
   equal-token flat context exactly past the memory horizon" (real, CI-clean) — plus regime-
   dependent mechanism choice. Suggested title (red-team candidate 2): "When Does Hierarchy Pay?
   A Memory-Horizon Study at Matched Token Budgets".
