# Session summary — VQ decision, uncertainty maps, the prediction-blob root cause, and a working recipe

Dates: 2026-06-20 → 2026-06-21. Branch: `feat/uncertainty-maps-128`. GPU: RTX 4060 Ti (16 GB).
This is the detailed record: the decisions, the evidence, the insights, what's built, and the plan.

---

## 0. TL;DR

- **Decision: dropped VQ.** The stated want ("a probability distribution over codes") was really *uncertainty
  maps*, which the existing continuous **GMM head already provides**; VQ-at-the-predictor had already failed
  (composite-index blob) and the HVQ paper-repo is action-segmentation, not reusable. Built on the existing
  continuous HVP repo instead.
- **Delivered:** entropy/uncertainty maps (B&W, white=certain), a 2→8→32 (128px) topology, a 15-agent
  component review with fixes, and a full root-cause of the long-standing **prediction blob**.
- **The blob is the BOT next-latent prediction mean-regressing, and it scales with per-frame motion** —
  *not* a tokenizer/representation defect (decoding the true next latents is sharp).
- **It's fixable.** A recipe — **more temporal context (T=17) + a larger BOT-focused predictor + an explicit
  warp head** — turns blobs into **recognizable predictions at 64px** on both fast in-plane (R1) and moderate
  SO(3) (R2).
- **Literal 2→8→32 (128px) is engineering-blocked**, precisely: the essential lever (T=17 context) is the
  attention *score matrix* (17408²) and OOMs at 128 on 16 GB. The unblocker is **true windowed attention on
  BOT** (now implemented + correctness-verified on the working tree; needs a memory probe + the long run).
- **Next steps (agreed):** (1) windowed/Flex BOT attention → unblock 128; (2) warp + distributional residual
  → sharper SO(3) *and* restore entropy maps; (3) ablate the levers.

## 1. Starting context & goal

The project (SEED-Voken → the clean `hierarchical-video-prediction` repo) had fought a **gray "blob"** in the
predicted frames across many sessions. The user's goal: **hierarchical video prediction with coarse→fine
"2 → 8 → 32" generation, ideally VQ at the bottom for a probability distribution over codes, continuous inside,
BLT as the reference, single-step (AR not a priority), "decent results that at least work / look normal."**

Two sibling repos were in play: the working continuous predictor (`hierarchical-video-prediction`) and the
HVQ paper repo (to consider reusing for VQ).

## 2. Decision 1 — drop VQ (analysis-driven)

A multi-agent analysis + adversarial critique established:
- **HVQ is not reusable** — it's *unsupervised action segmentation* (1D MS-TCN + stacked shrinking-codebook
  VQ → Hungarian-matched labels); no spatial hierarchy, no decoder/generator. Only the lucidrains VQ library
  pattern transfers.
- **VQ-at-the-predictor already failed** in SEED-Voken: a monolithic K-way head can't predict an FSQ composite
  index, and the *factorized* per-channel fix was implemented and **still blobbed** (the real cause was upstream:
  rotation re-coding + FSQ boundary chaos).
- **The user's real need was uncertainty maps**, not discrete tokens. The committed **continuous GMM head
  already yields a sampleable distribution** (validated: best-of-8 +0.56→+1.18 dB on SO(3)).
- → **Build on the existing continuous HVP repo; add uncertainty maps; do 2→8→32 by resolution.** (Memory:
  `decision-hvp-vq-dropped-uncertainty-maps`.)

## 3. What was built (consolidation)

- **Entropy/uncertainty maps** — `hvp/eval/uncertainty.py` + `scripts/uncertainty_map.py` + an in-training hook
  saving B&W maps to `<out>/val_strips/` (white=certain, black=uncertain). Verified on the `so3_gmm` checkpoint:
  white background, black on the moving shape.
- **2→8→32** — `topology.image_size=128` with the existing tap schedule derives BOT 32 / MID 8 / TOP 2 (verified).
  128px SO(3) data via `scripts/gen_data_so3_128.py`.
- **15-agent component review** (single-shift path), with adversarial verification:
  - **S1** (the "recon 30 dB but pred 13.5 dB" gap the user flagged): **not a bug** — the single-step pixel
    *ceiling* through the multi-rate shifted decode is ~22.8 dB (not the 30 of recon); the predictor captured
    a fair fraction of that. Added honest metrics (oracle ceiling + captured-fraction, changed-region, BOT-only).
  - **S2** (the flagship run left zero step checkpoints): periodic saves were never stamped. Fixed: stamped +
    pruned + atomic checkpoints + a wall-clock save timer.
  - Plus: MMSE-mean + clamp in the pixel metric, gradient accumulation, a consecutive-NaN stall canary, a
    reshuffling loader (replacing `itertools.cycle`, which replayed a fixed order and cached an epoch in RAM),
    and zero-spatial / sequence-length topology guards.

## 4. The blob — discovery & root cause

The first long 128px run looked numerically healthy (recon 34 dB, "changed-lift +2.3 dB") but the **predicted
frames were blobs** — the user caught this. A decode-variant diagnostic (`scripts/debug_prediction.py`,
decoding the predicted next latent as mean / sample / mode / BOT+oracle-coarse, plus an oracle ceiling) plus a
root-cause workflow with adversarial critique established:

- **Tokenizer/decoder are fine** — decoding the *true* next latents is sharp (the "oracle" row).
- **The BOT next-latent prediction is the blob** — on SO(3), oracle-everything = 19.8 dB sharp, but swapping in
  the *predicted* BOT collapses to 12.6 dB. The whole gap is the BOT prediction.
- **Mean-regression**: MSE/NLL training minimizes to the conditional mean of plausible next frames = a centered
  blob; **blur scales with per-frame motion**.
- **Disproven alternatives** (the critic corrected an initial misattribution): it is *not* the multi-rate
  hierarchy/coarse stages (oracle coarse doesn't rescue the BOT blob; current-coarse only helps on slow data),
  *not* the (collapsed) GMM (sampling already blobs; the motion is ~deterministic so there are no modes to
  capture). (Memory: `finding-hvp-prediction-blob-rootcause`.)

The motion–sharpness wall, measured (64px Z-only unless noted):

| motion (per frame) | pred PSNR | look |
|---|---|---|
| slow 4–10° | ~21 | recognizable |
| moderate 8–16° | ~22–23 | recognizable / sharp |
| fast 15–45° | ~17 | rounded blob |
| SO(3) 15–45°, 128px | 12.6 | formless blob |

## 5. The warp head & the recipe (R1, R2)

- **Warp head** (`head="warp"`, `predictor/cascade.py`): predict a per-cell 2D flow, `grid_sample` the
  *detached* current latent (detail is resampled → stays sharp), + a zero-init residual. Alone it was only a
  marginal +0.3–0.9 dB (estimating the flow is as hard as the regression) — but it composes with the other levers.
- **R1** (`configs/research_r1.yaml`): on the previously-always-blob **fast in-plane** case, the recipe
  **more temporal context (T=17) + larger BOT-focused predictor + warp** → recon 34.2 dB, pred **~21 dB**
  (~54% of the oracle ceiling), **recognizable oriented shapes** (`logs/debug_r1_final/`). The fast-motion blob
  was a **capacity/context** problem, not an intrinsic single-step wall.
- **R2** (`configs/research_r2.yaml`): same recipe on **moderate SO(3)** (real 3D rotation) → recon 34.5 dB,
  pred **~20 dB**, **recognizable rotating cuboids** (vs the 12.6 dB blob), with a notably **stronger hierarchy
  lift `mid_casc +0.10`** (vs ~+0.03 in-plane) — the coarse cross-attention earns its keep on 3D rotation.
  SO(3) leaves a larger oracle gap (self-occlusion the warp can't resample).

## 6. The 128 / 2→8→32 memory wall + verdict

- The two levers that make R1/R2 work **OOM at 128** (BOT is already 32²×9 = 9216 tokens): T=17 → 17408 tokens,
  and a larger BOT both exceed 16 GB.
- **Gradient checkpointing** (`predictor.grad_checkpoint`, added) drops peak 19→8.5 GB and **fits the larger
  BOT at 128** — but a 128 run with larger-BOT + warp + BOT-focus **at T=9 still blobs** (pred plateaus ~15.6,
  lift ~0). So **T=17 temporal context is the *essential* lever**, and it's the one checkpointing can't help
  (it's the attention *score matrix*, not activations).
- **Verdict:** literal 2→8→32 at recognizable quality is gated on **true windowed/Flex attention on BOT** (or a
  bigger GPU). The science is proven at 64px (16→4→1); 128 is an engineering scale-up.
- A `lambda_pred` bug was caught mid-run and fixed: `so3_128.yaml`'s 0.02 was calibrated for the GMM-NLL scale;
  the warp head uses MSE and needs the l2-scale weight (0.25).

## 7. Windowed attention (WIP on the working tree, uncommitted)

To afford T=17 at 128, implemented **true block-windowed self-attention** in `hvp/attention/sdpa.py`
(`SelfAttention.s_window`): partition the (T,H,W) grid into non-overlapping `w×w` spatial blocks and attend
within each across causal time, so the score matrix is per-block `(T·w·w)²` instead of global `(T·H·W)²` —
**real memory savings** (a dense windowed *mask* saves none). Coarse stages stay global (tiny); cross-window /
global context comes from the cascade's cross-attention (the BLT design). Threaded `s_window` through
`CascadeStageBlock` / `CascadeStagePredictor` (the per-stage self-mask becomes the per-block mask).
**Status: implemented + correctness-verified** (block-local, causal, shape-correct; default `s_window=0` path
unchanged, full test suite green). **Not yet done: a memory probe at 128 T=17, a config, and the long run.**

## 8. Key insights (durable)

1. **The blob ≠ a representation defect.** Tokenizer/decode are fine; the predictor mean-regresses. Decoding the
   *oracle* next latents is the right ceiling to judge against (~20–28 dB here, not recon's 30+).
2. **Blur scales with per-frame motion.** Moderate motion is recognizable out of the box; fast/3D motion needs help.
3. **For fast motion the levers are capacity + temporal context (T=17), not the output head.** The warp head is a
   minor contributor; T=17 is the dominant, *necessary* lever (the 128 control proves it).
4. **The hierarchy earns its keep — more on 3D rotation** (mid_casc rising 0.03→0.10→0.24 from in-plane→SO(3)→128).
5. **Latent VE ≠ pixel sharpness.** Decent latent variance-explained can coexist with a pixel blob — judge in
   pixels against the oracle ceiling, not by latent VE alone.
6. **Uncertainty maps require a distributional/stochastic output.** The deterministic warp head produces none;
   they return with a distributional residual (Step 2).
7. **Engineering hygiene that mattered:** honest oracle-relative metrics (a +2.3 dB "changed-lift" hid a blob),
   stamped/atomic checkpoints, a stall canary, and *looking at the images* (not just PSNR).

## 9. Plan & next steps

1. **Windowed/Flex attention on BOT → unblock literal 2→8→32.** *(Highest value; partly done — see §7.)*
   Remaining: memory-probe T=17 at 128 with the block window (expect a large drop from 17408²); add an
   `so3_128` config with `stage_s_window=[w,0,0]` + T=17 + larger BOT (+ grad_checkpoint if needed); golden-test
   the windowed path more thoroughly; run the long 128 SO(3) job; compare pred/images to the 64px proof.
   *Risk:* non-overlapping windows lose cross-window context — mitigated by the cascade's cross-attention; if
   insufficient, add shifted (Swin-style) windows or use FlexAttention with a sliding-window mask_mod.
2. **Warp + distributional residual → sharper SO(3) AND restore entropy maps.** The warp can't hallucinate
   newly-revealed faces under self-occlusion; add a small generative residual (a per-cell Gaussian/`gaussian`-head
   variance, or a MAR-style per-token diffusion head) on top of the warped mean. This makes the output
   sampleable → **entropy/uncertainty maps come back** and become more meaningful (true predictive uncertainty,
   incl. occlusion). Wire the in-training uncertainty hook to the new head.
3. **Ablate the levers** (T=17 vs larger-BOT vs warp, individually, at 64px) — already strongly indicated that
   T=17 is dominant; a clean ablation confirms it for the writeup.
4. **Deferred:** AR rollout (de-prioritized by the user), best-of-N eval with the distributional head, multi-seed
   error bars.
